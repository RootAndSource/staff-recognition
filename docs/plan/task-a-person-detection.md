# 实现方案：任务 A 员工检测（人员检测 + 工装识别）

状态：待评审
版本：v0.1
日期：2026-08-17

依据：`docs/requirements/task-a-person-detection.md`（v0.2）、`docs/research/notes/person-detection-tracking.md`、`docs/research/notes/staff-identification.md`

读者：研究生（负责编码实现）

## 1. 目标回顾

单摄像头实时监测员工开会场景（教室/会议室，天花板与墙壁交叉处，斜俯视），检测画面中所有人员，并识别其是否穿着工装（红色背心或短袖），为每个人员维护持续 ID，为任务 B/C/D 的按人统计打基础。

## 2. 总体流程

```
摄像头/视频 → 逐帧读取 → 人员检测（YOLO）→ 多目标跟踪（ByteTrack）
→ 裁剪上半身 ROI → HSV 红色工装匹配 → 工装/未工装标签 + 人员 ID
→ 画面叠加显示 + 结构化输出
```

## 3. 模块与实现要点

### 3.1 视频输入

- 输入：本地视频文件或 RTSP 流（固定机位，斜俯视，会议场景）
- 用 OpenCV `VideoCapture` 读取；分辨率建议 ≤1080p，必要时降采样保证实时性
- 丢帧策略：处理不过来时丢弃旧帧、保持最低延迟

### 3.2 人员检测

- 工具：ultralytics（YOLO 预训练权重，COCO），推理时只保留 `person` 类别
- 模型选择：无 GPU 用 YOLO11n，有 GPU 用 YOLO11s/YOLOv8s（备选 RTMDet）
- 置信度阈值：0.3-0.5 起步，现场实测后标定
- 文献参考：YOLO（Zotero RNACS4BD）、YOLOv10（UW4MF6WP）、RTMDet（GIKCUUJN）、YOLO 综述（ATMZQ3BM）

### 3.3 多目标跟踪与人员 ID

- 首选 ByteTrack（ultralytics 内置或官方实现），维护 `track_id`
- 关键参数：匹配 IoU 阈值、丢失帧缓冲（如 30 帧）、新轨迹确认帧数
- 会议场景的起身/入座、短暂遮挡容易造成 ID 切换，需实测；不达标时对比 OC-SORT / StrongSORT
- 文献参考：ByteTrack（8HSPQ4HT）、DeepSORT（TXHKP6Q8）、OC-SORT（5W57RFUI）、StrongSORT（2KRKVTSM）、MOT 综述（ITNB8829）

### 3.4 工装识别（红色背心/短袖）

- 从检测框裁剪**上半身 ROI**：斜俯视视角下躯干约占检测框上部，建议从 y∈[0.2, 0.6] 区间开始实验标定
- HSV 红色判定：H∈[0,10]∪[170,180]，S、V 下限现场标定（如 S≥80、V≥80）
- 红色像素占比 ≥ 阈值（如 8%-15%）→ 判为“穿工装”；阈值用现场画面标定
- 光照归一化：对 ROI 做直方图均衡化或灰度世界颜色校正，降低明暗影响
- 文献参考：行人属性识别综述（IEFVK5G5）、俯视角度颜色特征可用性（QWV8F5XJ）

### 3.5 输出

- 实时画面：检测框 + 标签（员工 / 工装 / 未工装）+ 人员 ID 叠加显示
- 结构化输出：时间、人员 ID、bbox、工装标签、置信度，JSON 逐帧或降频写出，供任务 B/C/D 使用

### 3.6 性能与运行

- ≥15 FPS；连续运行 ≥1 小时稳定不崩溃；同时在场 5-15 人
- 全部本地处理：视频与画面不出本机、不联网、不上传任何平台

## 4. 环境与依赖

- Python 3.10+；`ultralytics`、`opencv-python`、`numpy`
- 建议 conda/venv 独立环境；模型权重和代码本地保存

## 5. 验证与验收

- 数据：现场会议视频（隐私数据，本地标注与评估，禁止外传）
- 指标：
  - 工装识别准确率 ≥95%（人工抽查 100 帧，同时统计精确率/召回率）
  - 人员检测：记录漏检/误检情况并说明原因
  - ID 稳定性：同一人持续出现 10 分钟内，ID 切换次数尽可能接近 0
  - FPS ≥15；连续运行 ≥1 小时不崩溃
- 评估方式：脚本抽帧 + 人工标注表（CSV/表格，本地保存）

## 6. 风险与对策

- 俯视角度导致 ROI 偏移：第二版引入 YOLO-Pose 关键点（肩/髋）定位上半身
- 红色背景/红衣人员误报：限定判定区域、提高占比阈值；必要时采集少量现场数据微调
- 光照变化：颜色归一化；按早/中/晚分别标定阈值
- 遮挡与 ID 切换：ByteTrack 缓冲参数调优，必要时换 OC-SORT
- 多人密集：适当提高检测置信度阈值、优化跟踪关联参数

## 7. 里程碑（建议工期）

- M1：读视频 → YOLO 检测 → ByteTrack 跟踪跑通（1-2 天）
- M2：工装颜色判断 + 实时画面叠加（2-3 天）
- M3：结构化输出 + 100 帧评估脚本与标注（2-3 天）
- M4：现场试运行 ≥1 小时 + 验收（1-2 天）

## 8. 验收口径

满足第 5 节全部指标即视为通过；与要求文档 `docs/requirements/task-a-person-detection.md` 逐条对应。
